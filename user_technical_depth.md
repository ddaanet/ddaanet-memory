The user engages deeply with LLM internals (attention, training dynamics, generation mechanisms, cost math) and pushes back when explanations are hand-wavy or mischaracterize the mechanism.

**How to apply:**
- Don't offer casual mechanism claims ("the model thinks X because Y") without grounding. Verify against actual transformer / training / Claude API documentation behavior.
- Cost math should be specific and checkable — input vs output pricing ratios, cache costs, break-even points. The user will catch sloppy arithmetic (saw this with skill re-reading math on 2026-04-23).
- Be willing to correct yourself mid-conversation. The user respects "I was wrong, here's the corrected reasoning" more than plausible-sounding deflection.
- When asked to "be contrarian" or "poke holes," deliver real pushback, not performative disagreement.
- Strawmanning and false dichotomies get called out directly. Reason cleanly.
